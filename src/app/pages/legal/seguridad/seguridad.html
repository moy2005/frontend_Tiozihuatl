1. Introducción y Objetivo

1.1 Propósito

Los presentes Lineamientos de Seguridad de la Información establecen el marco normativo y las directrices técnicas para proteger los activos de información del Instituto de Estudios Superiores Tiozihuatl (IEST) en el contexto del Sistema Integral Multiplataforma.

Módulos Cubiertos

Portal Web Institucional
Módulo de Biblioteca Digital
Venta de Revistas Digitales
Foros Académicos
Sistema de Recomendación
Base de Datos Institucional

1.2 Objetivos Específicos

  • Garantizar la confidencialidad, integridad y disponibilidad de la información institucional
  • Establecer controles de seguridad en todas las fases del ciclo de vida del software
  • Prevenir, detectar y responder a incidentes de seguridad informática
  • Cumplir con la normativa nacional e internacional en materia de seguridad
  • Proteger los datos personales conforme a la LFPDPPP
  • Minimizar riesgos derivados de amenazas internas y externas

4. Principios Fundamentales de Seguridad

Confidencialidad

Definición: La información solo es accesible por personas autorizadas.

Implementación:

  • • Cifrado de datos (SSL/TLS)
  • • Control de acceso basado en roles (RBAC)
  • • Clasificación de información
  • • Firmas de confidencialidad

Integridad

Definición: La información es exacta y completa, sin alteraciones no autorizadas.

Implementación:

  • • Validación de entradas de usuario
  • • Checksums y hashes
  • • Logs de auditoría inmutables
  • • Control de versiones

Disponibilidad

Definición: Los sistemas están accesibles cuando se necesitan.

Implementación:

  • • Uptime objetivo: 99.9%
  • • Redundancia de servidores
  • • Balanceo de carga
  • • Plan de recuperación ante desastres

Autenticidad

Definición: Verificación de identidad de usuarios y origen de información.

Implementación:

  • • Autenticación multifactor (MFA)
  • • Tokens JWT con expiración
  • • Firma digital de documentos
  • • Certificados SSL válidos

No Repudio

Definición: Imposibilidad de negar autoría o envío de información.

Implementación:

  • • Logs de auditoría detallados
  • • Timestamps en transacciones
  • • Registro de acciones críticas

Trazabilidad

Definición: Capacidad de rastrear las acciones realizadas en el sistema.

Implementación:

  • • Logs centralizados
  • • Correlación de eventos
  • • Retención de logs: 12 meses mínimo

6. Clasificación de la Información

NIVEL 1: PÚBLICA

Acceso Abierto

Descripción: Información destinada a difusión abierta.

Ejemplos: Noticias, convocatorias, programas académicos, calendario escolar

Controles: Mínimos, solo integridad de publicación

NIVEL 2: INTERNA

Uso Interno

Descripción: Información de uso interno del Instituto.

Ejemplos: Comunicados administrativos, procedimientos operativos, manuales de usuario

Controles: Acceso restringido a personal autorizado, no publicación externa

NIVEL 3: CONFIDENCIAL

Sensible

Descripción: Información sensible cuya divulgación podría causar daño al Instituto.

Ejemplos: Datos personales, historial de préstamos, información financiera, contratos, credenciales

Controles:

  • Cifrado en tránsito y reposo
  • Acceso basado en necesidad de conocer
  • Logs de acceso obligatorios
  • Prohibición de copia no autorizada

NIVEL 4: CRÍTICA

Máxima Protección

Descripción: Información cuya pérdida causaría daño severo.

Ejemplos: Código fuente, credenciales administrativas, llaves de cifrado, configuraciones de seguridad

Controles:

  • Cifrado fuerte (AES-256)
  • Autenticación multifactor obligatoria
  • Acceso limitado a personal específico
  • Auditoría continua
  • Prohibición de almacenamiento local

6.2 Manejo y Destrucción

Confidencial y Crítica: Borrado seguro (mínimo 3 pasadas) o destrucción física certificada

Interna: Eliminación estándar

Pública: Sin restricciones especiales

7. Seguridad Física y Ambiental

7.1 Control de Acceso Físico

  • Sala de servidores: Acceso restringido con tarjeta/llave
  • Videovigilancia en áreas críticas
  • Registro de visitantes a áreas sensibles
  • Escoltas obligatorias para personal externo

7.2 Protección Ambiental

  • Climatización adecuada (18-24°C)
  • Detectores de humo y sistemas contra incendios
  • UPS para servidores críticos
  • Protección contra desastres naturales

7.3 Seguridad de Equipos

  • Anclaje físico de equipos valiosos
  • Política de escritorio limpio
  • Bloqueo automático (5 min inactividad)
  • No instalación de software no autorizado

7.4 Dispositivos Móviles

  • Cifrado de dispositivos institucionales
  • Políticas MDM cuando aplique
  • Contraseña obligatoria
  • Reporte inmediato de pérdida/robo

8. Control de Acceso

8.2 Políticas de Contraseñas

✓ Requisitos Mínimos

  • • Longitud: Mínimo 8 caracteres
  • • Al menos 1 letra mayúscula
  • • Al menos 1 letra minúscula
  • • Al menos 1 número
  • • Al menos 1 símbolo especial (@#$%&*)

⚙️ Gestión

  • • Cambio obligatorio: Cada 90 días
  • • No reutilizar últimas 5 contraseñas
  • • Bloqueo: Después de 3 intentos fallidos
  • • Desbloqueo: Solo por Administrador

❌ Prohibiciones

• Información personal
• Contraseñas secuenciales
• Palabras del diccionario
• Compartir con terceros

9.1 Ciclo de Vida de Desarrollo Seguro (SDLC)

Seguridad integrada en todas las fases del desarrollo

1 FASE 1: Análisis y Diseño

Actividades:

  • • Identificación de riesgos
  • • Análisis de amenazas (STRIDE, DREAD)
  • • Definición de requerimientos
  • • Diseño de arquitectura segura

Entregables:

  • • Matriz de riesgos
  • • Especificación de controles

2 FASE 2: Desarrollo/Programación

Prácticas Obligatorias:

✓ Prevención de Inyección SQL
✓ Prevención de XSS
✓ Prevención de CSRF
✓ Gestión segura de sesiones
✓ Control de errores seguro
✓ Manejo seguro de archivos

Ejemplo SQL Seguro: Siempre usar consultas parametrizadas, nunca concatenación directa

Simulación de ataques reales

Escaneo automatizado

En CI/CD pipeline

Headers de seguridad configurados
Modo debug deshabilitado

  • Monitoreo continuo de amenazas

11. Gestión de Incidentes de Seguridad

11.2 Clasificación de Incidentes

CRÍTICO < 1 HORA

Compromiso de datos críticos, interrupción total del servicio

ALTO < 4 HORAS

Compromiso de datos confidenciales, interrupción parcial

MEDIO < 24 HORAS

Vulnerabilidad explotada sin compromiso de datos

BAJO < 72 HORAS

Intento fallido de ataque, anomalía menor

11.3 Proceso de Gestión de Incidentes

1

DETECCIÓN Y REPORTE

Identificación del incidente y notificación inmediata al Administrador

Canales: Correo, teléfono, formulario web

2

CONTENCIÓN

Aislar sistemas afectados, cambiar credenciales, bloquear IPs maliciosas

Objetivo: Prevenir propagación del incidente

3

ERRADICACIÓN

Eliminar causa raíz, limpiar malware, aplicar parches

Objetivo: Eliminar amenaza completamente

4

RECUPERACIÓN

Restaurar sistemas desde respaldos, validar integridad, monitoreo intensivo

Objetivo: Restablecimiento seguro de servicios

5

LECCIONES APRENDIDAS

Documentación, análisis de causa raíz, actualización de procedimientos

Objetivo: Mejora continua

11.4 Notificación de Incidentes

A usuarios afectados:

Incidentes que comprometen datos personales: máximo 72 horas

Notificación interna:

Dirección General: Inmediata para incidentes críticos

15. Sanciones y Consecuencias

Incumplimiento de Lineamientos

El incumplimiento de estos lineamientos puede resultar en:

Sanciones Administrativas

  • Amonestación verbal o escrita
  • Suspensión temporal de acceso al sistema
  • Revocación permanente de credenciales
  • Proceso disciplinario según reglamento institucional

Consecuencias Laborales/Académicas

  • Para personal: Suspensión o terminación de contrato
  • Para estudiantes: Sanciones académicas según reglamento
  • Para proveedores: Rescisión de contrato

Consecuencias Legales

  • Acciones legales por daños causados
  • Denuncia ante autoridades competentes
  • Responsabilidad civil y/o penal

Nota Importante

La gravedad de las sanciones dependerá de la naturaleza, intencionalidad y consecuencias del incumplimiento. Cada caso será evaluado individualmente por el Comité de Seguridad de la Información.

16. Glosario de Términos

ARCO
Derechos de Acceso, Rectificación, Cancelación y Oposición sobre datos personales
Cifrado
Proceso de convertir información en código para prevenir acceso no autorizado
CSRF
Cross-Site Request Forgery - Ataque que fuerza al usuario a ejecutar acciones no deseadas
DDoS
Distributed Denial of Service - Ataque que busca hacer un recurso no disponible
Firewall
Sistema que previene accesos no autorizados a una red
JWT
JSON Web Token - Estándar para crear tokens de acceso
Malware
Software malicioso diseñado para dañar o infiltrar sistemas
MFA
Multi-Factor Authentication - Autenticación de múltiples factores
OWASP
Open Web Application Security Project - Organización de seguridad en aplicaciones web
Phishing
Técnica fraudulenta para obtener información confidencial
RBAC
Role-Based Access Control - Control de acceso basado en roles
RPO
Recovery Point Objective - Punto de recuperación objetivo
RTO
Recovery Time Objective - Tiempo de recuperación objetivo
SSL/TLS
Protocolos de seguridad para comunicaciones cifradas
WAF
Web Application Firewall - Firewall de aplicaciones web
XSS
Cross-Site Scripting - Vulnerabilidad que permite inyectar scripts maliciosos
